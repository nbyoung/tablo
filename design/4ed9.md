# Design 4ed9: Plumbing command

The `tablo` command reads a Tableaux project from a Git repository and writes one result per run: any of the ten views as data, the validator's diagnostics, a commit trailer, or its own version. It is the contract of the three front ends, so this design fixes four things: the command-line vocabulary, the envelope every result travels in, the exit codes, and the Go API that returns the same envelope without a process. Four choices shape it. A front end links tablo as a library and the command is a thin shell over that library (D1). Each view is a subcommand named as its mockup file is named, and the person parameter is `--person` (D2, D3). Without `--ref` the command reads the working tree on `HEAD` (D4). The output is a function of the repository and the resolved parameters, and the envelope states both (D6, D7). D*n* is decision *n* under [Decisions at review](#decisions-at-review).

The drafts under [`4ed9/`](4ed9/) fix the shapes; the implementation turns them into files at the paths below.

| Draft                                                    | Lands as                                 | Holds                                                                  |
|----------------------------------------------------------|------------------------------------------|------------------------------------------------------------------------|
| [`4ed9/envelope.schema.yaml`](4ed9/envelope.schema.yaml) | `envelope.schema.yaml`, embedded         | The envelope as JSON Schema 2020-12, with the parameters each command echoes |
| [`4ed9/usage.txt`](4ed9/usage.txt)                       | `internal/cli/usage.txt`, embedded       | The text `tablo --help` prints: every command, option and exit code     |
| [`4ed9/mockup-lines.txt`](4ed9/mockup-lines.txt)         | `internal/cli/testdata/mockup-lines.txt` | The 68 view command lines the Markdown mockups print, as `tablo` spells them |

## The model

### Library or executable

**Recommendation: each front end links tablo as a Go library; the executable serves scripts, hooks, CI and the conformance run.** This settles decision 4 of [tabloio's design 1422](https://github.com/nbyoung/tabloio/blob/main/design/1422.md) and keeps its assumptions A1 to A5 (see A11). The library returns an `Envelope` value; the command encodes that same value and adds nothing, so the two cannot disagree (T10).

A long-running front end holds one `Repository` and calls `Load` once per repository change. `Load` reads the files and the history once and returns an immutable `Snapshot`; every view, pane and page then derives from memory. The parts cost this much on the Tableaux tooling plan (37 tasks, 71 files, 140 commits), on one WSL2 host:

| Step                                                            | Cost    |
|-----------------------------------------------------------------|---------|
| Start one process (`tablo version` in the prototype)            | 2 ms    |
| Read the 71 files at a ref: `git ls-tree -r` and one `git cat-file --batch` | 6 ms |
| Read the same files from the working tree                       | under 3 ms |
| One `git log --raw` pass with trailers over all 140 commits     | 36 ms   |

So a reload costs the linked front end about 45 ms per change on this plan, whatever the number of views it shows, and the cost grows with the length of the history. The same front end running the executable pays that load, a process start, a JSON encode and a JSON decode for every view it shows after every change: three times for a terminal that shows a grid, a pane and a queue, and once per page for the daemon. The prototypes, which start one `git` process per fact, show where an unshared load goes: 34 ms for one status view (886d) and 97 ms for one structural view (493e) on the six-task weather station.

What linking costs:

- **A fix travels through three releases.** A front end release pins one tablo version, so a validator or derivation fix reaches a tabloio, tablotui or tableaud user only when that front end releases again. With the executable, one tablo release serves all three.
- **The Go API becomes a compatibility surface.** While tablo is at `v0`, a break raises the minor version and each front end raises its floor deliberately, as the three READMEs already state. This design keeps the exported surface small for that reason.
- **Two tablo versions can stand on one machine**: the one a front end links and the `tablo` binary a hook runs. Design 1422 pairs them in CI; the schema version below detects the rest.
- **Each front end binary carries the YAML and JSON Schema modules and the embedded schemas.** `git` stays a requirement either way (A2).

What running the executable costs instead: the per-view load above; a second binary beside every front end, at a compatible version that only a run can check; and the view types written twice, or read as untyped maps, in each front end. PLAN.md gives each tool one binary, and the three READMEs already plan a `require` line for tablo; linking keeps both.

| Path                              | Holds                                                                                          |
|-----------------------------------|------------------------------------------------------------------------------------------------|
| `github.com/nbyoung/tablo` (root) | The public API below: `envelope.go`, `params.go`, `snapshot.go`, `trailer.go`, `errors.go`, `yaml.go`, `envelope.schema.yaml` |

### The command line

`tablo [options] <command> [arguments]`. One table drives the parser, the library's parameter check and every front end. The command names are the mockup file names.

| Command      | VIEWS.md section       | Mockup         | Task                    | Person                        | Own options                                   | Opens at detail for               |
|--------------|------------------------|----------------|-------------------------|-------------------------------|-----------------------------------------------|-----------------------------------|
| `gates`      | Gate definition        | `gates.*`      | `--task`, default none  | not taken                     |                                               | every role                        |
| `task <id>`  | Task definition        | `task.*`       | the argument, required  | `--person`, default nobody    |                                               | every role                        |
| `authority`  | Authority delegation   | `authority.*`  | `--task`, default the root | `--person`, default nobody |`--proposed`                                   | owner, authority, assignee        |
| `assignment` | Task assignment        | `assignment.*` | `--task`, default the root | `--person`, default nobody |                                               | owner, authority, assignee        |
| `queue`      | Contributor work queue | `queue.*`      | `--task`, default the root | `--person`, default the viewer | `--brief <id> <gate>`                       | contributor, agent, reviewer, authority |
| `blockage`   | Work-blockage tree     | `blockage.*`   | `--task`, default the root | `--person`, default nobody |                                               | owner, authority, contributor     |
| `tableau`    | Global tableau         | `tableau.*`    | not taken               | `--person`, default nobody    | `--window <n>` or `--columns <gate>,…`; `--historical` | owner                    |
| `context`    | Contextual tableau     | `context.*`    | `--task`, or the person | `--person`, default the viewer when no task | `--window <n>` or `--columns <gate>,…`; `--historical` | assignee, contributor, authority |
| `history`    | History                | `history.*`    | `--task`, default the root | `--person`, default nobody | `--ref <from>..<to>`                          | every role; provenance for the owner |
| `audit`      | Audit                  | `audit.*`      | `--task`, default the root | `--person`, default nobody | `--stale <days>`, default 7; `--now <date>`   | owner, authority; provenance for the owner |

Every view also takes `--role <role>` and `--level glance|detail|provenance`. The other commands are `validate`; `trailer authorised <id>`, `trailer reviewed <id> <gate>`, `trailer reaffirmed <id>` and `trailer model <identifier>`, each with `--no-check`; and `version`.

**Options for every command**: `-C <dir>`, the directory the search for `.tableaux` starts from, default `.` (the nearest `.tableaux` at or above it, up to the repository's root, as the Loader finds it; decided at review, 4f60 decision 7); `--ref <ref>`; `--trunk <branch>`, the branch the caller names, which the method reads only when `version.yaml` and `origin/HEAD` name none; `--replace <url>=<dir>`, repeatable, the local clone of a subproject named by absolute URL; `--viewer <email>`; `--json` or `--yaml`; `--help`.

**Parsing.** The parser is about sixty lines over one table of option names and arities, with no dependency:

1. Options stand before or after the command, in any order: `tablo -C dir --ref r validate --json` (design 1422) and `tablo task e9c6 --ref 3cdae52` (the mockups) both parse. `--` ends the options.
2. An option's values are the next arguments. `--name=value` also works for an option of one value. `--brief` takes two.
3. `-C` is the only single-letter option. A long option written with one hyphen is a usage error that names the two-hyphen form.
4. An option given twice is a usage error, except `--replace`.
5. The first word that is no option is the command; `task` and `trailer` take the words after it; any other extra word is a usage error.
6. An option the command does not take is a usage error. So are `--window` with `--columns`, `context` with both `--task` and `--person`, `--brief` with `--level` or `--role`, a range on any command but `history`, `--json` with `--yaml`, `queue` or `context` with no person and no viewer, and a malformed value: a task id that is not four lowercase hexadecimal digits, an email without one `@`, a gate key outside `^[a-z][a-z0-9_-]*$`, a ref that starts with a hyphen, a three-dot range, a date that is not `YYYY-MM-DD`, a negative window, a stale age below one.

**The viewer** is `--viewer`; else `GIT_AUTHOR_EMAIL` when it is set; else `git config user.email` in `-C`; else nobody, an observer. The envelope names the viewer and the roles that email holds anywhere in the project, in README.md's order: owner, authority, assignee, contributor, agent, reviewer; `observer` alone when it holds none.

**The level** resolves in this order: `--brief` gives provenance; else `--level`; else the level `--role` opens the view at; else the level the viewer's roles open it at. A view opens at provenance where the table says so, at detail for a role in its last column, and at glance otherwise; of several roles the deepest level wins. The envelope states the resolved level, and `data` holds what that level and the levels below it show (A5).

### What a command reads

| `--ref`           | Files                         | History                 | `source` in the envelope                                    |
|-------------------|-------------------------------|-------------------------|-------------------------------------------------------------|
| absent            | The working tree under `-C`   | `HEAD`                  | `worktree: true`, `ref` the branch `HEAD` names, or `HEAD`  |
| a commit-ish      | That commit, through Git objects | That commit          | `worktree: false`, `ref` as given                           |
| a tree            | That tree                     | none                    | `commit: null`; `validate` alone accepts it                 |
| `<from>..<to>`    | The commit `<to>`             | `<to>`, bounded by `<from>` | `from: { ref, commit }`; `history` alone accepts it     |

`-C` may name a directory below the repository root; the project is then the nearest `.tableaux` at or above that path, in the working tree or in the tree at the ref, and the envelope names the directory resolved. A directory with no `.tableaux` at or above it is rule P1, and the message names the directory the search started from and the root it reached. `<from>..` reads `<to>` as `HEAD`, and `..<to>` is the whole history up to `<to>`. A tree is what `git write-tree` gives a pre-commit hook: the validator then runs every rule that needs no history (A3). The command calls `git` with `--end-of-options` before every ref.

### The envelope

With `--json` or `--yaml`, and by default for the ten views, standard output holds exactly one envelope: eight keys, always present, in this order. [`4ed9/envelope.schema.yaml`](4ed9/envelope.schema.yaml) fixes every field.

| Key           | Holds                                                                                                                        |
|---------------|------------------------------------------------------------------------------------------------------------------------------|
| `schema`      | `tablo/1`                                                                                                                    |
| `command`     | The command name                                                                                                             |
| `source`      | What the command read: `ref`, `worktree`, `commit` in full, its author `date`, `from`, the `trunk` with how it resolves (`stated`, `inferred`, `caller`, `undetermined`), and `on_trunk`. Null when the command reads no repository |
| `project`     | `tableaux`, `root`, `title` and `owner`. Null when the files give no root task                                               |
| `viewer`      | `email` and `roles`, for a view; null otherwise                                                                              |
| `params`      | The parameters the command takes, each present, with every default written in and null when unset; `{}` for a command that is no view |
| `data`        | The command's result as one object, or null when the project's errors prevent the derivation (A4)                            |
| `diagnostics` | What the loader and the validator report about the source, sorted; `[]` when they report nothing                             |

`validate` writes `data: { valid, errors, warnings, information }`. `trailer` writes `{ trailer, kind, task, gate, model }`. `version` writes `{ version, tableaux, schema }`. A view writes its own data (A5 to A8), which repeats nothing the envelope states. Every list is an array in display order, and an empty list is `[]`, never null and never absent. How a front end renders an empty view stays with its renderer.

A **diagnostic** carries `severity` (`error`, `warning`, `information`), `code` (the rule id of corpus/RULES.md, A3), `message`, and where they apply `path` (relative to `-C`, starting `.tableaux/`, with `/` on every host), `line`, `col`, `task`, `gate`, `commit` and `trailer`. The order is by path, a diagnostic without one first, then line, column, code, task, gate, commit and message.

**Plain forms.** Three commands write plain text unless `--json` or `--yaml` asks for the envelope: `validate` writes one line per diagnostic, `<path>:<line>:<col>: <severity>: <code> <message>`, dropping the parts a diagnostic lacks, and nothing for a clean project; `trailer` writes the line; `version` writes `tablo 0.1.0 (tableaux 0.3, schema tablo/1)`.

**JSON** comes from `encoding/json` with a two-space indent, no HTML escaping and one final newline; key order is the declaration order of the Go types, and no consumer may read meaning into it. **YAML** is the same document respelt by a small emitter that walks the JSON tokens: block mappings and sequences indented by two spaces, `[]` and `{}` for empty ones, every string value written by `strconv.Quote`, a key plain when it matches `^[a-z][a-z0-9_]*$` and is none of `null true false yes no on off y n`, quoted otherwise. The emitter keeps the gate and state symbols legible, where `gopkg.in/yaml.v3` escapes every character beyond the Basic Multilingual Plane, and it quotes every id, so `07e0` and `1000` stay strings in any YAML reader.

### Exit codes

| Code | Meaning                                                                                              | Standard output       | Standard error                         |
|------|------------------------------------------------------------------------------------------------------|-----------------------|----------------------------------------|
| 0    | The command ran; no diagnostic is an error                                                           | The result            | empty                                  |
| 1    | The command ran; at least one diagnostic is an error                                                 | The result, complete  | empty                                  |
| 2    | The command line is wrong                                                                            | empty                 | `tablo: <message>` and `Run 'tablo --help' for usage.` |
| 3    | The repository, or a ref, task or gate the command line names, cannot be read                        | empty                 | `tablo: <message>`                     |

Code 1 reads `diagnostics` alone: a warning never fails a run, the command has no strict mode, and an audit finding that is no validator rule changes no exit code. A directory without `.tableaux` is rule P1, an error diagnostic and exit 1. Code 3 covers: no Git repository at `-C`; `git` missing or failing; a bare repository without `--ref`; an unknown ref; a tree given to any command but `validate`; a well-formed task or gate that the project lacks in `--task`, `--brief`, `--columns` or `trailer`; for `trailer reviewed`, a gate that does not apply to the task; a failed write. `--help` prints the usage text on standard output and exits 0. A message names the option or the value at fault; its wording is no contract.

### Determinism

The same repository state and the same resolved parameters give the same bytes, on every host. The envelope holds no time of the run, no host name and no absolute path, and only `version` states the tablo version; commits appear in full, since an abbreviation depends on the clone; dates are author dates as Git records them. The environment enters in two places, and an option replaces each: the viewer (`--viewer`) and the date staleness counts from (`--now`, default the host's local date, for `audit` alone). The envelope echoes both, so a consumer sees every input that shaped the output. The library reads neither the environment nor the clock: its caller passes `Viewer` and `Now`.

### Schema version

`schema` is `tablo/<n>`, and one number covers the envelope and the `data` of every command. The first release is `tablo/1`. A change that removes, renames or retypes a key, changes the meaning or the default of an option, removes a command, or adds a value to a closed list (levels, roles, severities) raises `n`. A new key, a new command, a new option or a new diagnostic code does not: every object stays open and a consumer ignores what it does not know. While tablo is at `v0` a raise of `n` comes with a raise of the minor version.

A front end learns of an incompatible tablo in two ways. One that links the library learns at build time: its `go.mod` floor names one `v0.N` series and the Go types change with the schema. A consumer of the executable compares `schema` with the number it knows and refuses any other; `tablo version --json` answers that with no repository at hand, and exits 0 anywhere.

### The Go API

The root package exports this and no more. `Source`, `ProjectInfo`, `Viewer` and `Diagnostic` mirror the objects of the same name in the schema, field for field and in its key order.

```go
// SchemaVersion names the output schema: the envelope and every command's data.
const SchemaVersion = "tablo/1"

// EnvelopeSchema is envelope.schema.yaml, the JSON Schema of the envelope.
var EnvelopeSchema []byte

// Options are what a caller states about a repository beyond its files.
type Options struct {
	Trunk   string            // the branch the caller names; read when version.yaml and origin/HEAD name none
	Replace map[string]string // an absolute subproject URL to the directory of its local clone
}

// Open finds the Git repository that holds dir and returns a handle on the
// project whose .tableaux lies in dir. It reads no project file.
func Open(ctx context.Context, dir string, opt Options) (*Repository, error)

// A Repository is a long-lived handle on one project directory, safe for
// concurrent use. Resolve returns the full id of the commit a ref names.
// Load reads the project and its history once: the ref "" reads the files
// from the working tree and the history from HEAD; a commit-ish reads both
// from that commit; a tree reads the files alone, for Validate. A project
// that fails validation still loads, and the snapshot carries the diagnostics.
type Repository struct{ /* unexported */ }
func (r *Repository) Resolve(ctx context.Context, ref string) (string, error)
func (r *Repository) Load(ctx context.Context, ref string) (*Snapshot, error)

// A Snapshot is one project at one source. It is immutable and safe for
// concurrent use, and it computes each derived fact once.
type Snapshot struct{ /* unexported */ }
func (s *Snapshot) Source() Source             // what Load read
func (s *Snapshot) Project() *ProjectInfo      // nil when the files give no root task
func (s *Snapshot) Diagnostics() []Diagnostic  // sorted, never nil
func (s *Snapshot) HasTask(id string) bool     // whether the project holds the task
func (s *Snapshot) GateKeys() []string         // the gate keys of gates.yaml, in order
func (s *Snapshot) Viewer(email string) Viewer // the roles the email holds; an observer when none

// View checks and resolves p for v, derives the view and returns its
// envelope. The error is a *UsageError, a *NotFoundError or a *ReadError;
// an invalid project is no error: the envelope then has nil Data.
func (s *Snapshot) View(ctx context.Context, v View, p Params) (*Envelope, error)

// Validate returns the validate command's envelope.
func (s *Snapshot) Validate() *Envelope

// CheckTrailer returns a *NotFoundError when t names a task the project
// lacks or, for a reviewed trailer, a gate that gates.yaml lacks or that
// does not apply to the task.
func (s *Snapshot) CheckTrailer(t Trailer) error

// A View names one of the ten views by its command name: Gates, Task,
// Authority, Assignment, Queue, Blockage, Tableau, Context, History, Audit.
type View string

// Level is "glance", "detail" or "provenance". Role is "owner", "authority",
// "assignee", "contributor", "agent", "reviewer" or "observer".
type Level string
type Role string

// Params focus a view. The zero value asks for every default. Check returns
// a *UsageError when p sets a field v does not take or holds a malformed
// value, by the rules of the command table. Narrow returns p without the
// fields v does not take, for a front end that carries one state across views.
type Params struct {
	Task       string   // a task id
	Person     string   // an email
	Viewer     string   // whoever runs the tool; "" is an observer
	Role       Role     // the role whose level the view opens at
	Level      Level    // the level, overriding the role's
	Window     *int     // tableau, context: columns either side of the next gates; nil is 1
	Columns    []string // tableau, context: the gate keys to show, in place of a window
	Historical bool     // tableau, context: show the marks of historical junctions
	Proposed   bool     // authority: proposed tasks only
	Brief      *Brief   // queue: write this one item as a brief
	Stale      int      // audit: days after which a status is stale; 0 is 7
	Now        string   // audit: the date staleness counts from, YYYY-MM-DD; required
	From       string   // history: the ref the range starts after; "" is the whole history
}
type Brief struct{ Task, Gate string }
func (p Params) Check(v View) error
func (p Params) Narrow(v View) Params

// An Envelope is the result of one command: what the library returns and
// what the command encodes. Field order is the key order of the output.
type Envelope struct {
	Schema      string       `json:"schema"`
	Command     string       `json:"command"`
	Source      *Source      `json:"source"`
	Project     *ProjectInfo `json:"project"`
	Viewer      *Viewer      `json:"viewer"`
	Params      Resolved     `json:"params"`
	Data        any          `json:"data"` // a view's typed data (A5 to A8), or nil
	Diagnostics []Diagnostic `json:"diagnostics"`
}
func (e *Envelope) JSON() []byte  // the JSON encoding above
func (e *Envelope) YAML() []byte  // the YAML respelling of JSON()
func (e *Envelope) ExitCode() int // 1 when a diagnostic is an error, else 0

// Resolved holds a command's parameters with every default written in. It
// marshals the keys its command takes, each present and null when unset, in
// the order task, person, window, columns, historical, proposed, brief,
// stale, now, role, level; for a command that is no view it marshals {}.
type Resolved struct {
	View View
	Params
}

// A Trailer is one of the four commit trailers of SYNTAX.md. Line returns it
// as Git writes it, with no newline, or a *UsageError when a field is
// missing, extra or malformed.
type Trailer struct {
	Kind  string // "authorised", "reviewed", "reaffirmed" or "model"
	Task  string // for the three task trailers
	Gate  string // for reviewed
	Model string // for model: printable ASCII with no space
}
func (t Trailer) Line() (string, error)

// A UsageError reports parameters a command or a view does not accept: exit 2.
// A NotFoundError reports a well-formed ref, task or gate that the repository
// or the project lacks: exit 3; Kind is "ref", "task" or "gate".
// A ReadError reports a repository that cannot be read: exit 3.
type UsageError struct{ Msg string }
type NotFoundError struct{ Kind, Name string }
type ReadError struct{ Op string; Err error }
```

Inside the root package one table joins the views to their tasks, and `internal/cli` exports one function:

```go
// A deriver computes one view's data from a snapshot and checked, resolved
// parameters. It returns errNotDerivable when the project's errors prevent
// the derivation; View then returns the envelope with nil Data.
type deriver func(ctx context.Context, s *Snapshot, p Params) (any, error)

// derivers names each view task's function once; nothing else calls them.
var derivers map[View]deriver

// Run executes one tablo command line and returns its exit code. It writes
// the result to stdout and, on exit 2 or 3, the message to stderr. It reads
// the environment for the viewer and the clock for --now's default, through
// two package variables a test replaces, and nothing else outside -C.
func Run(ctx context.Context, args []string, stdout, stderr io.Writer) int
```

`Run` parses, calls `Open`, `Load` and then `View`, `Validate` or `CheckTrailer`, and encodes. `version`, `trailer model` and `trailer --no-check` open no repository.

### The trailer command

`trailer` composes one line of SYNTAX.md#commit-trailers, ready for `git commit --trailer`: `Authorised: <id>`, `Reviewed: <id> <gate>`, `Reaffirmed: <id>` or `Model: <identifier>`. It reads the project at the source as every command does and refuses, with exit 3, a task the project lacks and, for `reviewed`, a gate that `gates.yaml` lacks or that does not apply to the task: the two things rule H1 warns of after the fact. `--no-check` composes the line from its syntax alone, for a caller with no project at hand. `model` names no task and checks nothing but the identifier. The command does not check who commits: whether the committer is an authority or the reviewer is a fact the write commands read from a view.

### Kept and dropped

From [`prototype/4ed9`](../prototype/4ed9/README.md) the design keeps the dispatcher, `-C` and `--ref`, the reading through `git`, the keys `schema`, `command`, `data` and `diagnostics`, the four exit codes, the plain trailer line and the diagnostic's `severity`, `code`, `path` and `message`. It drops `view <name>` for one subcommand per view; `status`, which the tableau and the task view answer; the commit list `history` printed, for the history view; the key `ref`, which `source` replaces; sorted keys, for declared order; options before the command only; JSON as the default of `validate` and `version`; the exit 3 for a missing `.tableaux`, which is P1; and both hand-written YAML readers. The prototype's four questions have these answers: `tablo/1`, raised by a change to `data` as much as to the envelope; a plain trailer line; exit 1 on an error and no strict mode; `git` as a subprocess (A2).

## Conformance to the texts

The command table names, per view, the [VIEWS.md](https://github.com/nbyoung/tableaux/blob/main/VIEWS.md) section and the mockup the view reproduces. tablo emits data and no form, so a level maps to content alone: at the resolved level `data` holds what the section's Levels paragraph lists for that level and the ones below. The owner's rulings stand in the table: `--window`, `--columns` and `--historical` belong to `tableau` and `context` and are usage errors elsewhere, the eight list-shaped views carry every gate, and a historical junction carries no mark unless the caller gives `--historical`. All 68 view command lines in the Markdown mockups fit the table once `--for` reads `--person` (T2).

The design departs from the texts in four places, each a decision below: the default source is the working tree, where VIEWS.md says `HEAD` (D4); an option a view does not take is an error, where VIEWS.md says it has no effect (D8); `person` defaults to nobody on eight views, where VIEWS.md says the viewer (D5); and tablo's own README and this task's description name `view`, `status`, `--at` and `--for` (D2, D3). The trailer command composes lines and reads no trailer block, so it does not meet the place where README.md and SYNTAX.md differ.

## Decisions at review

The owner decided each question this design raised on 2026-10-06, together with the cross-design rulings of that review; a decision the review did not reach stands as the design states it, accepted with the design.

1. **Library or executable.** Decided by the owner on 2026-10-06: a front end links tablo as a library and loads one snapshot per change; the executable serves scripts, hooks, CI and conformance, as [Library or executable](#library-or-executable) states. The ruling binds every front end design of the wave; `b618`'s `Source` becomes an in-process adapter, as its A8 foresaw. The alternative, every front end running the executable, costs one load per view per change and a second binary per front end, and frees a tablo fix from three front end releases.
2. **`--person`.** Decided by the owner on 2026-10-06: the person parameter is `--person` everywhere, as VIEWS.md names it and as the queue, context and tableau mockups write it; `--for` goes. This binds tabloio's Read commands (5ca9), renderers (e3ed, c48a, a3cc, 9167, which print the command line in `task.md`, `audit.md` and `assignment.md`), Agent briefs (e4c7) and Write commands (b618); tablotui's 679b and 171b; and tableaud's 49ce, its templates and 6160, whose query names follow the keys of `params`: `person`, `ref`, `task`, `level`. The nine mockup lines that write `--for` stay as drawn; VIEWS.md's log records the ruling. The alternative was `--for`, shorter and already in tablo's README, which now changes.
3. **One subcommand per view, named as the mockups name them.** Decided by the owner on 2026-10-06: `gates`, `task <id>`, `authority`, `assignment`, `queue`, `blockage`, `tableau`, `context`, `history`, `audit`, with `--historical` and `--brief <id> <gate>` as the mockups write them. The task's description, which names `view` and `status`, stays as authorised; this entry records the departure. The alternative kept `tablo view <name>` and `status`, as the description and tablo's README had them, and `--brief TASK:GATE`, as prototypes 5ca9 and 49ce had it. By the same ruling, `--ref` is the ref option in every tool, where tablotui's `171b` and tableaud's `6160` wrote `--at`.
4. **The default source is the working tree on `HEAD`.** Decided by the owner on 2026-10-06: without `--ref` the files come from disk, so the daemon and the terminal show an edit before its commit, and `--ref HEAD` gives the committed state. VIEWS.md's parameter table changes from `HEAD` of the checkout to the working tree. The alternative followed VIEWS.md and added a `--worktree` option. In a working-tree read a submodule reads at its checkout's `HEAD` (4f60 decision 8), and the Loader reports which submodules it read on disk.
5. **The default of `person`.** Decided by the owner on 2026-10-06: the viewer for `queue` and for `context` without a task; nobody for the other eight, where the mockups show "no person marked" and "person: everyone". VIEWS.md's parameter table gains the per-view default. The alternative, tableaud's `49ce` decision 7, added `authority` and `task`; it is withdrawn there. This binds every design D2 names.
6. **The level resolves in tablo, from `--level`, then `--role`, then the viewer's roles.** Decided by the owner on 2026-10-06: tablo keeps `--role` and the role-based default, as stated; the rule sits in one place, and the envelope names the viewer, the roles and the level. tabloio's Read commands (5ca9 decision 4) take `--level` alone, glance by default, since their output is a file, and pass the level explicitly. The alternative had tablo emit provenance always and each front end choose. The last column of the command table is this design's reading of each view's Roles paragraph; the view tasks confirm it row by row.
7. **Staleness counts from `--now`, default today.** Accepted with the design, as stated. It is the one place the clock enters, the envelope echoes it, and a script that needs the same bytes tomorrow passes it. The alternative counts from the date of the commit in view, which the static export (6160 decision 8) passes through this option.
8. **An option a view does not take is a usage error.** Decided by the owner on 2026-10-06: a mistyped option never passes for a default; `Params.Narrow` serves a front end that carries one state across views. VIEWS.md, which said such a parameter has no effect, changes to agree. The alternative accepted it silently.
9. **One schema number for the envelope and all data**, `tablo/<n>`, raised by any incompatible change and tied to the minor version at `v0`. Accepted with the design, as stated. The alternative versions each view's data apart, which lets one view change without the others and gives every consumer ten numbers to check.
10. **Plain by default for `validate`, `trailer` and `version`; JSON by default for the views; a `model` trailer beside the three the task names.** Accepted with the design, as stated. The alternative writes the envelope always and leaves `Model:` to the callers.
11. **Where the project is, and a project that is missing.** Decided by the owner on 2026-10-06, from the Loader's review (4f60 decision 7): the project is the nearest `.tableaux` at or above `-C`, up to the repository's root, and the envelope names the directory resolved. A directory with none at or above it is rule P1, an error diagnostic and exit 1, as [Exit codes](#exit-codes) already states and as the Conformance design (4b4f decision 4) requires.
12. **What tablotui's designs accepted on 2026-10-07 take from the library.** Recorded on 2026-10-07 from tablotui's `0afa`, `f394` and `518e`, which the owner accepts that day. `--viewer` stays the plumbing's word, and the two live front ends name the viewer `--as` (`f394` decision 1); tablotui follows this design's order for the default identity (`f394` decision 2). `f394` A1 to A3: `Snapshot.Viewer` returns the roles an email holds anywhere in the project, in the order owner, authority, assignee, contributor, agent, reviewer, and `observer` alone when it holds none, at the cost of no load; the seven names are a closed list; `tableau` and `context` take `Params.Viewer` and `Params.Role`, an explicit `Level` overrides the role's, a role the viewer does not hold is no error, and the envelope echoes `viewer.email` and `params.role`. `0afa` A1, A2 and A5: the adapter maps an envelope's `Data` into its own types; with no `Level` and a `Viewer` a view answers at the level the viewer's roles open it at and states that level; the queue with no person and no viewer is a usage error; a view derives from the snapshot in memory. `518e` A8 and A11: tabloio and tablotui sit on one minor of tablo, and the actions read no key of the envelope.
