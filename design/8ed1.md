# Design 8ed1: Temporal views

This task gives the last two views as data: the history, what each commit does to each task in view, and the audit, the findings of a project as a reader lists them. It builds on the packages, the levels and the builders of [design 493e](493e.md) and [design 886d](886d.md), and on the Audit of [design dada](dada.md), and derives nothing: the history selects and joins the events of `Facts.History`, and the audit selects and lists a `*audit.Report`. Six choices shape it (D*n* is decision *n* under [Decisions at review](#decisions-at-review)). A line is one commit on one task and holds the task definition's `Event`, unchanged, so an event has one shape in every view and the corpus's events read straight off the lines (D1). A subproject's events join the lines from detail on, in the Derivation's order, and the counts cover the project's own lines (D2). A range is Git's `A..B`, read through `Log.Reaches`; a subproject's event lies in it when the commit its link reads at the start does not reach it; a proposal is a line the trunk's tip does not reach (D3). A line's effect is one of nine words (D4). The data adds seven types to `view` and five names to the schema (D5). `views.Query` gains `From` and `Minimum`, and no `Stale` or `Now` (D6).

## The model

### Packages

| Path             | Adds                                                                                                     |
|------------------|----------------------------------------------------------------------------------------------------------|
| `view`           | `history.go`: `History`, `HistoryProvenance`, `EventCount`, `Day`, `Line`, `LineDetail`, `LineProvenance` |
| `internal/views` | `history.go`: `History`; `audit.go`: `Audit`; in `views.go`, `Query.From` and `Query.Minimum`              |

`internal/views` imports `internal/audit` for `Report`, `Row` and `Finding`, and nothing else new; `internal/audit` imports no view, so no cycle forms. The audit's data types stand in `view/audit.go` on `main` (dada), and this task declares none of them again. [`model.md`](8ed1/model.md) holds every declaration with its doc comment.

### The history

`History(f, q)`; type `view.History`. The **subject** is `q.Task`, the root when it is `""`, and the data always names it. The function walks `f.History()` once and keeps an event when:

1. its task lies in the subject's subtree (`builder.subtree`);
2. it is the project's own, or the level is detail or provenance (D2);
3. `q.Person` is `""` or the commit's author email (README.md#history: "the commit's author as the actor");
4. the range holds it (D3): `q.From` is `""`; or, for an event of the project, `f.Log().Reaches(q.From, commit)` is false; or, for an event taken from a subproject, no link of its task reads a commit at `q.From`, or `f.Sub(link).Log().Reaches(pinned, commit)` is false, where `pinned` is the `Where.Commit` of the snapshot's facts that `f.At(q.From).Snapshots(task)` gives for the link's url.

Consecutive kept events that share the commit, the task and, for a taken event, the subproject task and the url make one **line**; `Facts.History` already orders them so (author time; the project's events before a subproject's; oldest first in the pass; display order; the kinds). `line.events` holds each through `event(e)` of `task.go`, so it reads exactly as `TaskProvenance.Events` does: `date`, `commit` in full, `by`, `kind`, `recorded`, `gate`, `pin` with `url`, `old` and `new`, and `subproject` with `url` and `task` on a taken event.

`proposal` is true on a line of the project when the source is off the trunk (`!f.OnTrunk()`), the trunk has a tip, and `f.Log().Reaches(tip, commit)` is false: the branch adds the commit (VIEWS.md#history). A taken line is never a proposal; without a trunk, no line is (as 886d decision 9 and dada decision 6 read "no trunk").

**Detail** adds to each line, from `at`, the facts of the project the line comes from (`f`, or `f.Sub(link)` for a taken line), and `task`, its task there:

| Key             | Is                                                                                                                                          |
|-----------------|---------------------------------------------------------------------------------------------------------------------------------------------|
| `after`         | `builder.status` of `at.At(commit).Status(task)`, null where those files lack the task. A parent rolls up and a snapshot reads the subproject's past, both as `At` gives them; `date` and `recorder` stay `""`, since the files at a commit state neither (`At`: "no fact of the history") |
| `unchanged`     | `at.At(p).Status(task)` agrees with `after` in kind, gate, state, reason and note for some parent `p` of the commit: a merge that brings in a status changes nothing, as `Log.Changed` reads a merge |
| `subject_after` | On a line of the project whose task is not the subject: the subject's status at the commit, by the same rule. Else null                     |
| `effect`        | The first row of the table in [`model.md`](8ed1/model.md#view-the-history) that holds, read from `at.AuthorisationAt(task, commit)` and each reviewed event's `Effect` (D4) |
| `model`         | The commit's first `Model:` trailer, `""` for none                                                                                          |
| `check`         | The first status or reaffirmed event of the line whose `Reading.Verdict` is not `NoModel`, as the task definition writes a `ModelCheck`; else null |
| `committer`     | The committer's email where it differs from the author's; else `""`                                                                         |

**Provenance** adds `commit`, `builder.commit` of the line's commit, and to the view `commands`, the two commands of README.md#history over the source commit, with `<from>..` before it in a range: one over the files of the subtree's tasks, `.tableaux/tasks` and `.tableaux/status` whole for the root, with each submodule path a snapshot of the subtree names; one with `-E --grep='^(Authorised|Reaffirmed): (<ids>)$' --grep='^Reviewed: (<ids>) '`, `[0-9a-f]{4}` for the root. Without a history `commands` is `[]`.

**The counts** read the project's own lines alone, so they are equal at every level: `events`, `commits` (distinct), `kinds` (all six, zeros included), and `days`, one per author date in the order the lines first name it, each with the kinds it holds and no zero.

### The audit

`Audit(f, r, q)`; type `view.Audit`, as `dada` declares it. `r` is the report `audit.Run` returns for the facts in view, never nil: with a refusal `snapshot.go` writes `data: null` and calls no view. The function:

1. keeps, through `r.Keep`, every finding when the subject is the root, else those whose task lies in its subtree, and of them those whose resolver is `q.Person` when it names one (dada A3: a finding with no task, or with a task the tree lacks, stays under the root alone);
2. writes `errors`, `warnings` and `information` from `Counts()`, `most` from `Most()`, and at detail `silent` from `Silent()`, each of the kept report, whatever the minimum;
3. lists `Rows(q.Minimum)`, one `view.Finding` per row, as [`dada/model.md`](dada/model.md#from-a-finding-to-the-data) states field by field, through the builders `ref`, `junction`, `status`, `requirement`, `authorisation`, `linkages` and `commit`; detail adds `files` and `message`, provenance `sentence`, `source`, `facts`, `commits` and `commands`.

A trial gives [`view/testdata/audit.provenance.json`](../view/testdata/audit.provenance.json), dada's golden data, as an equal JSON value, from `weather-station` at `main` with the diagnostics of `validate.Files` and `validate.Derived`, `Now` the source's date and the default age.

### Errors, determinism and cost

Neither function fails or panics; `snapshot.go` guarantees what 493e states, a `From` the pass holds, and a non-nil report (A1). Every list has a stated order; the functions read no clock, file or environment, and `TestImports` gains `internal/audit` alone. The detail level calls `At` once per commit of the lines and per parent, each kept by the Derivation: on the Tableaux tooling plan at `3cdae52` the whole history at detail, 338 lines, takes 13 ms after the load, and the umbrella's `main`, 565 lines, 62 ms on one WSL2 host. A range calls `Reaches` once per kept event, a walk bounded by the event's place in the pass.

### Kept and dropped

From [`prototype/8ed1`](../prototype/8ed1/README.md) the design keeps one pass serving every range and both ends, events from the commit that makes them, author-time order with the pass's order for ties, Git's `A..B`, and the status event's recorded values. It drops its `git log`, its `cat-file` batch and its YAML reader, for the Derivation's pass and the Loader; its stand-in audit and the tags `introduced`, `standing` and `resolved`; the pin's `note`, for `url`, `old` and `new`; the fourteen days and the range end as the audit's date; and its event records, for lines of the shared `Event`.

| Which findings an audit range reports        | None: the audit takes one ref and no range (4ed9 A8). Settled                                                                      |

## Conformance to the texts

The design implements [VIEWS.md](https://github.com/nbyoung/tableaux/blob/main/VIEWS.md) "History" and the view half of "Audit", with README.md#history and SYNTAX.md#history for the events. History, Data: author-time order, date, commit and actor (`events`), the committer where it differs, the recorded status, the pin's `url` and commits, the models, the status after each event replayed for a parent (`after`, `subject_after`), the subproject's events up to its pin, the branch's proposals. Parameters: task with its subtree, person, ref or range; no window (the ruling of 2026-10-05). Levels: glance the lines, detail the facts beneath them and the subproject's events, provenance the commit and the commands. Audit: task, person, ref, `stale` and `minimum`, the counts by severity, `most` and the rows, as dada words them.

Where a text is silent, or two disagree:

- **A line or an event.** VIEWS.md's glance says "one line per event"; its example and `history.md` join one commit's events on one task. A line holds the events, so both read off it (D1).
- **`task, authorised`.** VIEWS.md's example and `history.md` call a commit that adds a task file on the trunk `task, authorised`; SYNTAX.md makes `authorised` an event of a trailer alone. The data gives one `task` event and the effect `authorised_commit`, so picture 1 of `history.md` counts 7 events where it draws 8. The mockup stays as drawn.
- **Where a subproject's events stand.** VIEWS.md puts them at detail "between two pins"; `history.md` nests them under each pin with counts; the corpus lists them inline in time order. D2 places them inline from detail on; picture 2's counts, 13 events in 7 commits, 1 status and 12 pins over `0704a09..main`, come out as drawn.
- **Unchanged.** `history.md` writes "unchanged until the next event" against the line above; the data compares with the commit's parents, so a range's first line reads alike, and `0704a09`, a merge, reads unchanged as drawn.
- **The person.** VIEWS.md says "the events one actor made"; README.md#history makes the author the actor. The committer does not select.
- **A range and a subproject.** No text says how a range bounds a subproject's events; D3 bounds them by the commit the link reads at the start.
- **The effect.** VIEWS.md lists no effect; tabloio's 9167 decision 2 asks tablo for a key; D4 names the words.

**Findings about the umbrella**, none edited: `schemas/history.schema.yaml` and SYNTAX.md#history's table lack the key `subproject`, which corpus/README.md ("Expected results", `events[]`) and thirteen `expected.yaml` files state, and the schema's `additionalProperties: false` refuses it; the `pin` event the brief expected to miss stands in both since 9f3f.

## Decisions at review

1. **A line holds the shared `Event`.** One line per commit, task and subproject task, its `events` the task definition's `Event` unchanged, its other keys the line's facts. The alternative is 9167 A1's flat line with `kinds`, `status`, `gate` and `pin`, which cannot hold two reviews or two pins of one commit and gives an event a second shape. Binds tabloio `9167`, tablotui `0afa`, tableaud `9a9c`, tablo `4b4f` A9 and `493e` A4.
2. **A subproject's events join at detail, inline; the counts are the project's.** Glance lists the project's own lines and every level counts them; detail and provenance add the subproject's lines where the Derivation orders them, each marked by `subproject`. The alternative nests them under each pin with counts, as `history.md`, 9167 A2 and 9a9c A5 draw, which drops a same-repository subproject's events, since it has no pin, and loses the corpus's order. Binds `9167`, `0afa`, `9a9c`, `4b4f`.
3. **The range and the proposal read `Log.Reaches`.** A range keeps what its start does not reach; a subproject's event, what the commit its link reads at the start does not reach there; a proposal is a line the trunk's tip does not reach, off the trunk, and none without a trunk. The alternative reads a proposal from `Commit.Trunk` as 27a3 A4 states, which marks every commit a `--no-ff` merge brought into the trunk. Binds `27a3` A4, `9167` A5, `9a9c` A7.
4. **Nine effect words.** `authorised_commit`, `authorised_merge`, `authorised_trailer`, `proposed`, `handoff`, `accepts`, `stands`, `none` and `""`, by the table of [`model.md`](8ed1/model.md#view-the-history), an `enum`. The alternative keeps tabloio's three hyphenated keys, `authorised-commit` and its two siblings, against the underscore of every other word in the schema. Binds tabloio `9167` decision 2, tablotui `0afa` C9, tableaud `9a9c`.
5. **The public vocabulary.** `view` gains `History`, `HistoryProvenance`, `EventCount`, `Day`, `Line`, `LineDetail` and `LineProvenance`; `subject` is always a task, the root by default; the schema gains `view_history`, `view_line`, `view_day`, `view_event_count` and `view_line_effect`, and the `allOf` entries of both views' levels. The alternative leaves `subject` null for the root, as 9167 has it. Binds `4ed9` (T6), the three front ends.
6. **`Query` gains `From` and `Minimum`, not `Stale` and `Now`.** The report the audit view reads already holds the date and the age, which `audit.Input` takes (dada A1). The alternative follows the comment on `main` and 493e's model, which name `Stale` and `Now`, and passes them twice. Binds `493e`, `4ed9` (`query`).
