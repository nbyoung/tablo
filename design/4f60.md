# Design 4f60: Loader

The Loader reads one Tableaux project, from the working tree or from any Git revision, and returns it as an immutable value: the version, the gating, every task and status as written, every subproject a file links to, and the position of every value. It reads files and never history. Four choices shape it. The model is a value with no handle to Git behind it, so the Validator (8118) and the Derivation (27a3) are functions of it and their tests need no repository. The model and the Loader stay under `internal/`, so no front end links them. `gopkg.in/yaml.v3` parses, and the Loader types every scalar itself by YAML 1.2, so `40e8` is the same thing on every host. The `git` executable reads objects, at about 1.5 ms a process and three processes a project.

## The model

### Packages

| Path             | Holds                                                                                  | Imports                |
|------------------|----------------------------------------------------------------------------------------|------------------------|
| `internal/model` | The types below and the version rule. No input or output                               | The standard library   |
| `internal/git`   | The one place that runs `git`: discovery, `Run`, the blob batch                        | The standard library   |
| `internal/load`  | The Loader: sources, YAML reading, the typed build, subprojects, the fetch             | `model`, `git`, `yaml.v3` |

The README's layout shows the root package and `cmd/tablo` only; these three are the first packages below it, and the Validator, the Derivation and the Audit follow the same pattern. Nothing under `internal/` imports the root package, since the root package later imports them to serve the views. So the version rule moves: `ParseVersion`, `Accepts` and the two constants live in `internal/model/version.go`, and the root `version.go` keeps its four exported names as one-line wrappers, with `version_test.go` unchanged.

**No public surface.** This task exports nothing new from `github.com/nbyoung/tablo`. A front end never reads a task file, so it needs no task type; it needs view data, diagnostics and a way to name what to read, and the Plumbing command (4ed9) and the view tasks own that surface (A4). The model then changes freely between `v0` minors.

### The project

```go
package model

// Pos locates a value in a project file.
type Pos struct {
	File string // the path below .tableaux, with forward slashes; "" for the project itself
	Line int    // from 1; 0 when the fault has no line
	Col  int    // from 1, in Unicode code points; 0 when the reader names no column
}

// Kind is the kind of a YAML node under the YAML 1.2 core schema.
type Kind int

const ( Null Kind = iota; Bool; Int; Float; String; Seq; Map )

// Value is one YAML node as read: the untyped tree a schema validates.
type Value struct {
	Pos    Pos
	Kind   Kind     // what the tool takes the node as
	Read   Kind     // a scalar: the kind YAML 1.2 gives it as written; differs from Kind only at an id
	Text   string   // a scalar: its text as written, without quotes
	Quoted bool     // a scalar: written in quotes, as a block scalar or under !!str
	Items  []*Value // a Seq
	Fields []Field  // a Map, in file order; a repeated key is not here
}

// Field is one key of a mapping and its value.
type Field struct {
	Key    string
	KeyPos Pos
	Value  *Value
}

// Get returns the value of key in a Map, or nil.
func (v *Value) Get(key string) *Value

// At follows keys and sequence indexes, as a JSON Pointer's segments, and returns nil where the path ends.
func (v *Value) At(path ...string) *Value

// Plain returns the tree as map[string]any, []any, string, int64, float64, bool and nil,
// the form a JSON Schema validator takes. An Int beyond int64 becomes a float64.
func (v *Value) Plain() any

// Str, Int and Bool are typed fields as written. Node is nil exactly when the file omits the field.
type Str struct {
	V    string // the text of any scalar; "" for a collection
	Node *Value
}
type Int struct {
	V    int
	OK   bool // the node is an Int, or a Float with no fraction, that fits
	Node *Value
}
type Bool struct {
	V, OK bool // OK when the node is a Bool
	Node  *Value
}

// File is one file of the layout that the Loader read.
type File struct {
	Path string // below .tableaux
	Root *Value // nil when the file is empty or does not parse
}

// Project is one Tableaux project as its files state it at one place and moment.
type Project struct {
	Where       Location
	Exists      bool             // a .tableaux directory is there
	Files       []*File          // by path
	Stray       []string         // paths under .tableaux the layout does not name, by path
	Version     *Version         // nil when version.yaml is absent or does not parse
	Gating      *Gating          // nil when gates.yaml is absent or does not parse
	Tasks       map[string]*Task // by id: the file's name without .yaml, whatever it is
	Statuses    map[string]*Status
	Links       []*Link      // each distinct subproject the files name, by URL then commit
	Diagnostics []Diagnostic // the Loader's own, by file, line, column, code
}

// TaskIDs returns the keys of Tasks in byte order.
func (p *Project) TaskIDs() []string

// Location says where a project was read.
type Location struct {
	GitDir   string // the repository's common Git directory, absolute: the repository's identity
	Top      string // the working tree's root, absolute; "" in a bare repository
	Dir      string // the directory that holds .tableaux, relative to the repository root; "" at the root
	Ref      string // the revision asked for; "" for the working tree
	Commit   string // the commit read, in full; HEAD's for the working tree; "" for a bare tree or an unborn branch
	Worktree bool   // the files come from disk
}

// Version is version.yaml.
type Version struct {
	File                *File
	Tableaux, Trunk     Str
	Major, Minor, Patch int
	WellFormed          bool // Tableaux is major.minor.patch
	Accepted            bool // WellFormed, and the module accepts it
}

// Gating is gates.yaml. Each list is in file order and keeps an entry for every item written.
type Gating struct {
	File    *File
	Gates   []*Gate
	States  []*State
	Reasons []*Reason
}
type Gate struct {
	Key, Symbol, Name, Criteria Str
	Node                        *Value
}
type State struct {
	Key, Symbol, Synopsis Str
	Severity              Int
	Node                  *Value
}
type Reason struct {
	Key, Symbol, Synopsis Str
	Node                  *Value
}

// Task is tasks/<id>.yaml as written. Nothing here is inherited, defaulted or resolved.
type Task struct {
	ID                           string
	File                         *File
	Title, Description, Assignee Str
	References                   []*Reference
	Requires                     []*Requirement
	Junctions                    []*Junction // in file order
	Parent                       *Parent     // nil exactly when the file has no parent key
}
type Reference struct {
	URL, Text Str
	Node      *Value
}
type Requirement struct {
	ID             Str
	Subproject     *Subproject
	From, To, Text Str
	Node           *Value
}
type Parent struct {
	ID    Str
	Order Int
	Node  *Value
}

// Junction is one entry under junctions, with every field it states, whatever its kind.
type Junction struct {
	Gate                         string // the key as written
	KeyPos                       Pos
	Contributor, Model, Reviewer Str
	References                   []*Reference
	Subproject                   *Subproject
	Applies                      Bool
	Node                         *Value
}

// JunctionKind is what the fields of an entry make it.
type JunctionKind int

const (
	Plain         JunctionKind = iota // no subproject and no applies; {} is plain
	Recursive                         // subproject alone
	NotApplicable                     // applies alone, whatever its value
	Mixed                             // fields of more than one kind
)

func (j *Junction) Kind() JunctionKind

// Subproject is a subproject field, on a junction or a requirement, and what it leads to.
type Subproject struct {
	URL, ID, Commit Str
	Node            *Value
	Link            *Link // nil when URL is not a scalar
}

// Status is status/<id>.yaml as written.
type Status struct {
	ID                        string
	File                      *File
	Gate, State, Reason, Note Str
}
```

A task or a status exists for every file of that name that parses, whatever its content: a root that is no mapping gives a task with nothing set. A typed field is lenient where the schema is strict, so `title: [a]` gives a `Str` with a `Node` and no text, and the Validator reports the kind from `File.Root`. A field the schema does not name appears in `File.Root` only.

**Positions.** Every position is the value's own: the first character of a scalar, the `{` or `[` of a flow collection, the first key of a block mapping, the indicator of a block scalar. A key keeps its own position in `Field.KeyPos`, which serves an unknown field and a junction's gate. A column counts code points, as `yaml.v3` does: the trial reads `symbol: 🧱` and places the next key three columns on, not six bytes.

### Reading YAML

**The reader.** `gopkg.in/yaml.v3`, as the README states the owner decided, through `yaml.Decoder` and `yaml.Node` only; no struct decoding and no other package imports it. The prototype's `yaml.go` and its five sibling copies show the cost of a reader of our own: 1 781 lines between them, and none reads all of YAML.

**Typing.** The Loader ignores the tag `yaml.v3` resolves and types each plain scalar itself with the four patterns of the YAML 1.2 core schema; [`typing.yaml`](4f60/typing.yaml) fixes the table. `yaml.v3` keeps three YAML 1.1 readings that 1.2 drops: `0b10` and `1_000` as integers and `2026-09-01` as a timestamp, so a note that is a date stays a string here. A quoted scalar, a block scalar and a scalar tagged `!!str` are strings.

**Ids.** Under YAML 1.2, 12 000 of the 65 536 ids are numbers when unquoted: every all-digit id is an integer, and `40e8`, `07e0` and the like are floats. At the four places a task file names an id (`parent.id`, `requires[].id`, `requires[].subproject.id`, `junctions.<gate>.subproject.id`) the Loader takes any scalar as a `String` whose `Text` is the source text, so `07e0` stays `07e0` and `0010` stays `0010`; `Read` keeps the kind YAML gave it and `Quoted` says how the file writes it. `Plain()` then hands the schema a string, which settles finding F16, and the Validator raises T7 from `Read` and `Quoted`.

**What a Tableaux file does not use.** A second document, an anchor, an alias, a tag other than `!!str`, and a key that is not a scalar each give `L3`; the Loader reads the first document, reads an alias as null and reads a tagged scalar as untagged. A merge key is then an ordinary key named `<<`, which the schema rejects. No file in the five projects or the corpus uses any of these.

**Duplicate keys.** `yaml.Node` keeps both entries and says nothing. The Loader reports `L2` at the second key and keeps the first.

**A file that does not parse.** The Loader reports `L1` with the line the reader names and no column, keeps the `File` with a nil `Root`, makes no task or status from it, and reads every other file. [`broken/`](4f60/broken/) and [`broken.expected.txt`](4f60/broken.expected.txt) fix all of this. At review the owner gave the four codes rule ids and corpus entries in the umbrella's RULES.md, under the same names `L1` to `L4`, so the Loader raises rules of RULES.md here and names none of its own (decision 3).

### Reading a project

```go
package load

// Source names what to read.
type Source struct {
	Dir string // a directory in the repository; "" is the current directory
	Ref string // a revision or a tree; "" reads the working tree
}

// Options configure a Loader.
type Options struct {
	Replace  map[string]string // absolute URL to the path of a clone; wins over Git's configuration
	Fetch    bool              // fetch a URL that has no clone into the cache; off by default
	CacheDir string            // "" is os.UserCacheDir()/tableaux
	Git      string            // the executable; "" is "git"
}

// Loader reads projects. It is safe for concurrent use, and the projects it returns are
// immutable and may be shared between results.
type Loader struct{ /* options, the memo */ }

func New(Options) *Loader

// Load reads the project at src and every project it links to.
func (l *Loader) Load(ctx context.Context, src Source) (*model.Project, error)

// Fetch brings url into the cache so that commit is there.
func (l *Loader) Fetch(ctx context.Context, url, commit string) error

// Error is a failure to find what to read. Err is one of the four below.
type Error struct {
	Err    error
	Dir    string
	Ref    string
	Detail string // what git wrote to standard error
}

var (
	ErrNoGit        = errors.New("git is not on the path")
	ErrNoRepository = errors.New("not in a Git repository")
	ErrNoRef        = errors.New("the revision names no commit or tree")
	ErrNoWorktree   = errors.New("a bare repository has no working tree")
)
```

**Where the project is.** The project is the nearest `.tableaux` directory at or above `Source.Dir`, up to the repository's root, as Git finds `.git`. So a command run anywhere in a plain repository finds its plan, `-C lib` in a monorepo reads the project in `lib`, and a directory with no plan of its own reads the one that encloses it. At a revision the Loader looks in that revision's tree, in one `ls-tree` call over the candidate paths. Where none exists, `Load` returns a project with `Exists` false and no error, and the Validator reports P1.

**At a revision.** Three processes: one `rev-parse` that finds the Git directories and the prefix and resolves `<ref>^{commit}`; one `ls-tree -r -z --full-tree <commit> -- <dir>/.tableaux`; one `cat-file --batch` fed every blob id. A revision that is a tree and no commit, such as the id `git write-tree` prints in a pre-commit hook, costs one more `rev-parse` and leaves `Commit` empty. The Loader checks nothing out, and a bare repository serves.

**The working tree.** One process, the same `rev-parse` with `HEAD`, then the files from disk under `<top>/<dir>/.tableaux`, untracked ones included. The reading is what `git add -A` followed by `git commit` would record. `Commit` is HEAD's, for the history the Derivation reads, and is empty on an unborn branch.

**Files.** The layout names `version.yaml`, `gates.yaml`, `tasks/*.yaml` and `status/*.yaml`, each a regular file. Every other path under `.tableaux`, a symbolic link among them, goes to `Stray` with an `L4` warning and stays unread, so `tasks/g666.yml` does not vanish in silence.

**Git.** The `git` executable, as PLAN.md states for the family, and no library: Git's own code then reads worktrees, submodules, packed refs, alternates and both object formats, and the binary keeps one dependency on the host that every participant has. `internal/git` runs every command with `--no-optional-locks`, so a view that polls never takes the index lock, and with `-z` where a path prints. A revision follows `--end-of-options`. A command that addresses another repository (a submodule, a clone) runs with `--git-dir` and without the variables `git rev-parse --local-env-vars` lists: a trial with the `GIT_DIR` a hook inherits returns the parent's HEAD for the submodule.

**Cost.** A trial here, over 100 runs each (Git 2.47.3, Linux), measures 1.3 to 1.7 ms a process, whichever of `rev-parse`, `ls-tree`, `cat-file` or `config` it is, against 0.03 ms for an empty process, and 2.4 ms for the batch of the weather station's 11 blobs. Parsing costs about 0.05 ms a file: 759 files in 40 ms.

| Load                                         | Processes                 | About   |
|----------------------------------------------|---------------------------|---------|
| The working tree, no subproject              | 1                         | 2 ms    |
| A revision, no subproject                    | 3                         | 5 ms    |
| Each path a file links to, in total          | 1 more                    | 1.5 ms  |
| Each submodule or clone, first read          | 3                         | 5 ms    |
| Each submodule or clone, pin unchanged       | 1                         | 1.5 ms  |

**The memo.** A project read at a commit never changes, so a `Loader` keeps the last 256 it read whose links all resolved, keyed by Git directory, commit and directory. `tablotui` and `tableaud` hold one `Loader` for the process: a reload of the umbrella plan's working tree, 71 files and four submodules, then costs six processes and the parse, about 15 ms by the figures above. The table is an estimate from the unit costs; T24 measures it.

### Subprojects

The Loader resolves every `subproject` a file states, on a junction or a requirement, and the links of each project it reads in turn, eight links deep at most. The Validator and the Derivation then find the other project at `Subproject.Link.Project` and read nothing.

```go
package model

// Form is which of the method's three url forms a link takes.
type Form int

const (
	NoForm    Form = iota // the path leads nowhere
	Submodule             // a path that is a gitlink
	Directory             // a path that is a directory of the same repository
	URL                   // an absolute URL
)

// Problem is why a link has no project.
type Problem int

const (
	Resolved     Problem = iota
	Outside              // the path is empty, absolute or leaves the repository
	Missing              // nothing is at the path
	NoClone              // a submodule with no clone here; a URL with no mapping and no cache
	BadCommit            // a URL with no commit field, or one that is no full hash
	CommitAbsent         // the clone does not hold the commit
	NoProject            // no .tableaux is there
	TooDeep              // more than eight links from the project first asked for
)

// Link is one subproject as the Loader found it.
type Link struct {
	URL     string
	Form    Form
	Commit  string   // the commit the project is read at; "" for a Directory
	Project *Project // nil unless Problem is Resolved
	Problem Problem
	Detail  string
}
```

A `url` with a scheme and `://` is an absolute URL. Any other is a path relative to the repository root, as README.md states, cleaned with `path.Clean`; `.` names the root project.

| Form        | At a revision                                                                                  | In the working tree                                                              |
|-------------|------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------|
| `Submodule` | The path is a gitlink in the commit's tree; the pin is that gitlink                            | The path holds `.git`, and the pin is that checkout's HEAD, the commit `git add` records; else the index holds a gitlink, and the pin is it |
| `Directory` | The path is a tree; the Loader reads `<path>/.tableaux` in the same commit                     | The path is a directory; the Loader reads it from disk                           |
| `URL`       | The clone is `Options.Replace[url]`, else the path Git's configuration gives `tableaux.<url>.path`, else `<CacheDir>/clones/<sha256 of url>.git`; the Loader reads it at `commit` | The same |

A submodule's objects come from its checkout at `<top>/<path>` when one exists, else from `modules/<name>` under the Git directory and then the common Git directory, with `<name>` read from `.gitmodules` at the same revision. A stated `commit` never changes what the Loader reads on a path; comparing it with the pin (J17) and refusing it on a directory (J16) are the Validator's. Two entries that name one target share one `Link`, and two projects that name each other share each other, so the graph may loop and a consumer that walks it keeps a visited set.

**The network.** `Load` reads the cache and fetches nothing unless `Options.Fetch` is on, so a reload never waits on a host. `Fetch` clones `url` bare into the cache, or fetches every branch into an existing clone, and fails when `commit` is still absent. It accepts the schemes `https`, `http`, `ssh`, `git` and `file` and passes the URL after `--`, so a plan cannot name a transport that runs a command.

### What the Loader checks

The Loader reports what concerns reading and nothing about content.

```go
package model

// Severity is a diagnostic's weight, as RULES.md defines the three.
type Severity int

const ( Error Severity = iota; Warning; Information )

// Diagnostic is one finding of the Loader or the Validator.
type Diagnostic struct {
	Code     string // a rule id from RULES.md, or L1 to L4
	Severity Severity
	Pos      Pos
	Task     string // the task it concerns, when it concerns one
	Gate     string // the gate it concerns, when it concerns one
	Message  string
}
```

| Code | Severity | The Loader reports it when                                                              |
|------|----------|-----------------------------------------------------------------------------------------|
| `L1` | error    | A file cannot be read or is not YAML                                                    |
| `L2` | error    | A mapping states a key twice                                                            |
| `L3` | error    | A file uses YAML a Tableaux file does not: a second document, an anchor, an alias, a tag, a key that is no scalar |
| `L4` | warning  | A path under `.tableaux` is none the layout names                                       |
| `P4` | error    | `version.yaml` is well formed and the module does not accept it, by `Accepts`           |

P4 is the one rule of RULES.md the Loader raises, as its task states. Every other rule is the Validator's, the ones about presence included (P1, P2, G1, T1), since the model shows each as a nil or a name. The Loader raises nothing about a link: `Link.Problem` carries it. `Load` returns an error only when it cannot find what to read; the four `Err` values each mean exit code 3 in the command (A3).

**Deterministic.** The same files and the same clones give a deep-equal project: no clock, no host name, no environment beyond `Options` and the `tableaux.<url>.path` keys. Each slice has the order its comment states.

### From the prototype

[`prototype/4f60`](../prototype/4f60/README.md) shows that `ls-tree` and `cat-file` read a project at any ref, that every value keeps a line and column, and that `tablo.Accepts` decides P4; the design keeps all three. It drops the prototype's reader for `yaml.v3`, its process per file for one batch, and its checks T4, T6 and P3, which are the Validator's. The text above settles its four findings: `yaml.v3` under a typed model; the position of the value, with the key's kept beside it; `git` as a subprocess; `model.Diagnostic`.

## Conformance to the texts

The Loader builds no view. It follows SYNTAX.md "Layout" for the files, README.md "Junctions" for the three `url` forms, SYNTAX.md "`tasks/<id>.yaml`" for ids ("A tool takes an id as a string whatever scalar YAML yields") and README.md "Version" for P4. None of the brief's known open points touches it. It meets the texts in four places where they are silent or where it reads them narrowly:

- **A project in a directory.** SYNTAX.md puts the project "at the root of its Git repository", and README.md's same-repository form puts one in a directory. The Loader takes a project's place as a repository and a directory. A relative `url` stays relative to the repository root, as README.md says, so a project in `lib` names its sibling `tools`, not `../tools`.
- **A working tree.** The method fixes a subproject by a commit. Reading uncommitted files, the Loader takes a submodule at its checkout's HEAD and a same-repository directory from disk.
- **The cache.** README.md says a tool without a mapping "fetches the repository into a cache". The Loader does so only when asked (decision 5).
- **The schemas' version.** `schemas/README.md` in the umbrella has a tool compare the project with `schemas/version.yaml`. This module keeps the accepted version in `version.go` and embeds no such file, as its README states.

## Decisions at review

The owner decided each question this design raised on 2026-10-06, together with the cross-design rulings of that review; a decision the review did not reach stands as the design states it, accepted with the design.

1. **No exported surface.** Accepted with the design, as stated: the model and the Loader sit under `internal/`, and the front ends link only what 4ed9 and the view tasks export. The alternative exports the model as `github.com/nbyoung/tablo/model`, which lets a front end read a task and binds every later change to the model to a release. The owner also declined, for this wave, a shared watcher package under tablo (171b decision 6); a repository digest may join the exported surface later, once the Loader reports what it read.
2. **The YAML module.** Accepted with the design, as stated: `gopkg.in/yaml.v3` v3.0.1, as the README records. The module proxy dates that version 2022-05-27 and serves `go.yaml.in/yaml/v3` v3.0.5, dated 2026-07-26, from `github.com/yaml/go-yaml` with the same API; the alternative is that import path, a one-line change that the trial shows gives the same reading. PLAN.md still names `goccy/go-yaml`.
3. **Codes L1 to L4.** Decided by the owner on 2026-10-06, for the alternative: the umbrella's RULES.md gains a rule for a file that is not YAML, a repeated key, a YAML feature the files do not use, and a stray path, under the ids `L1` to `L4` with a corpus entry each, and the Loader raises those rules and names none of its own. This binds 8118 and 4b4f, and the umbrella commits the rules before 4b4f locks its copy.
4. **No anchors, aliases or tags.** Accepted with the design, as stated: the Loader reports each as `L3`. The alternative resolves an alias as YAML does, which needs a bound on expansion and gives one value two positions.
5. **Fetch on request.** Accepted with the design, as stated: `Load` never fetches unless `Options.Fetch` is on; the cache and `Fetch` exist. The alternative follows README.md to the letter and fetches on any load that lacks a clone, which makes a reload wait on a host.
6. **The mapping's home.** Accepted with the design, as stated: Git's configuration, `tableaux.<url>.path`, beside the `tableaux.project` key 1422 reads, with `--replace` over it. The alternative is a file of our own under the user's configuration directory.
7. **The nearest `.tableaux`.** Decided by the owner on 2026-10-06: the Loader searches upward from the directory named to the repository's root, as [Where the project is](#reading-a-project) states, and the envelope names the directory resolved. This binds 4ed9, 5ca9 and 171b, whose watcher watches the directory the Loader resolves. The alternative read the directory named and no other, so a command run in `src` reported P1. A directory with no `.tableaux` at or above it stays P1, an error diagnostic and exit 1, as this design and 4b4f decision 4 state.
8. **The working tree's pin.** Decided by the owner on 2026-10-06: a submodule reads at its checkout's HEAD when the Loader reads the working tree, for consistency with the working tree as the default source (4ed9 decision 4), and the Loader reports which submodules it read on disk so that a watcher knows what to poll. This binds 27a3, 171b, whose decision 4 is reversed, and 49ce. The alternative read the gitlink in the index, which shows a moved pin only after `git add`; 171b's alternative read the gitlink in the tree of `HEAD`.
